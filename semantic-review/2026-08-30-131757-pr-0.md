# Sealed revision-3 expanded-study execution with parent-finalized records

This revision closes the three blocking behaviors from the prior review: workers are selected from the sealed source manifest, workers publish only a nonfinal three-file bundle, and every producer-applicable trajectory value must be present and finite. The parent now owns final telemetry and the sole completion marker under the prospectively corrected revision-3 timing scope. Authorization remains ahead of scientific task/model construction and output creation, while preflight retains only its initialization-hashing exception. No new blocking concern was found; tests remain excluded by the active task constraint, and no scientific or preflight execution was performed.

**Watch for:** **confirmed — residual, non-blocking:** authorization, crash/resume, worker-isolation, and final-artifact paths still lack direct automated coverage; static approval is not scientific execution authorization.

**Verdict**: APPROVED

## High-level view

The arbitrary-worker path is gone. The parent resolves `scripts/run_expanded_studies.py` from the authorization-bound source manifest, launches that exact script with the current interpreter, and gives each child a context checked against argv, process ancestry, script identity, authorization bindings, and the parent-observed worker PID.

Record publication is split into nonfinal worker output and parent finalization. The worker writes trajectory, summary, and preliminary resources; only the issuing parent writes revision-3 timing and then `complete.json`. Resume rejects any record directory that is not the exact finalized four-file bundle.

Trajectory nullability is producer-specific rather than a nonfinite escape hatch. Applicable values must be finite during production and re-read; structural N/A cells must be blank with an exact annotation, and JSON artifacts cannot serialize nonfinite values.

Existing runtime metadata is validated on resume against the locked environment and clean authorized git state. The files remain untracked, so preflight cannot become authorization-ready in the current worktree; that is the intended gate, not an implementation defect.

## Manifest-bound worker launch and model-free authorization gate

The contract seals both expanded-study scripts and every Python source file (`configs/expanded_studies_execution.yaml:438-444`). `_worker_executable_binding` requires exactly one manifest entry for `scripts/run_expanded_studies.py` and verifies its path, size, and SHA-256 against the current regular file (`src/gradient_starvation/expanded_studies.py:415-452`). The parent rechecks this binding before each launch and constructs a fixed interpreter/script command rather than accepting an injected worker (`src/gradient_starvation/expanded_studies.py:2845-2872`).

```
external seal + exact preflight/source manifest
                    |
                    v
       parent verifies authorization
                    |
                    v
 sealed script + unique launch context
                    |
                    v
 child verifies argv / ancestry / PID / bindings
```

The child consumes the launch context before scientific work and checks script identity and process ancestry (`src/gradient_starvation/expanded_studies.py:2055-2129`). Its evidence is then matched to the parent-issued token digest, parent PID, parent-observed worker PID, and sealed executable (`src/gradient_starvation/expanded_studies.py:2133-2185,2230-2276`). **Prior finding 1 is fixed (confirmed):** production orchestration cannot substitute an arbitrary executable, and a direct worker without a matching context fails before task/model construction.

Revision 3 freezes cost timing as parent prelaunch through a sample after worker exit and bundle validation, before final resources and marker writes (`configs/expanded_studies_execution.yaml:274-287`; `src/gradient_starvation/expanded_studies.py:67-72,565-568`). ## Producer-specific finite trajectory contract

`_trajectory_applicability` freezes finite fields by study, method, condition, and—where ERM direct autograd exists—step (`src/gradient_starvation/expanded_studies.py:1561-1623`). Normalization rejects missing or nonfinite applicable values and permits NaN placeholders only for producer-inapplicable fields (`src/gradient_starvation/expanded_studies.py:1626-1711`). Artifact re-read requires applicable cells to be nonblank and finite, structural cells to be blank, booleans to match applicability, and both the structural annotation and CSV serialization to be canonical (`src/gradient_starvation/expanded_studies.py:1738-1838`). **Prior finding 3 is fixed (confirmed):** `nonfinite_fields` cannot censor an applicable diagnostic.

JSON loaders reject duplicate keys and explicit NaN/Infinity tokens; canonical output recursively rejects every nonfinite NumPy or Python float (`src/gradient_starvation/expanded_studies.py:293-361`; `scripts/check_expanded_studies_execution.py:299-339`). Loaded numeric artifacts are subsequently constrained by exact schemas, finite checks, or canonical equality. Record summaries are recomputed before acceptance, and final analyses are byte-compared with deterministic recomputation (`src/gradient_starvation/expanded_studies.py:2518-2531,2616-2622,3690-3707`).

## Exact resume and runtime acceptance

Before launching another worker, resume rejects extra IDs, requires every existing record to have exactly four finalized files, revalidates marker coordinates and input hashes, recomputes summaries, validates telemetry, and rejects reused launch-token digests (`src/gradient_starvation/expanded_studies.py:2596-2622,2727-2778`). An interrupted three-file worker bundle is explicitly nonrecoverable rather than rerun or accepted (`src/gradient_starvation/expanded_studies.py:2757-2762`), preserving the no-replacement rule.

Existing provenance must match authorized bytes. An existing runtime document is validated—not overwritten—against its exact schema, locked environment, clean git state, and timestamp (`src/gradient_starvation/expanded_studies.py:2624-2697`).
