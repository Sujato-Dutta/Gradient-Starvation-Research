# Authorization-gated expanded-study execution and analysis pipeline

This change implements initialization-only preflight, externally sealed execution, 192 Study-A plus 256 Study-B records, crossed-seed inference, and recomputed final artifacts. Preflight may hash initialized models, while scientific task/model construction, optimizers, and output are placed behind seal verification. The statistical path uses the fixed 4×8 matrices, shared 5,000-draw bootstrap, separate Holm families, exact eight-part CDC conjunction, and noncanonical comparator labels. Scientific execution should remain blocked because worker provenance can escape the seal, completion can precede resource finalization, applicable nonfinite diagnostics are accepted, and the new execution paths lack automated coverage.

**Watch for:** **confirmed — high:** an arbitrary `worker_command` can produce seal-attributed records outside the sealed source and isolation protocol; **confirmed — high:** resume can accept a marker written before worker/parent timing finalization; **confirmed — medium:** applicable numeric diagnostics may be blank if listed in `nonfinite_fields`; **confirmed — medium:** no test imports or exercises the expanded-study execution APIs.

**Verdict**: NEEDS_CHANGES

## High-level view

Preflight is the only pre-seal model-construction path and uses initialization hashing without forward or optimizer work. Both scientific entry points verify the external seal and current clean commit before task/model construction or output creation.

**Confirmed, high:** the orchestrator does not require the launched worker to be the source-manifest-bound worker. A caller can substitute any executable, while the exported direct-worker API and PID-only checks cannot establish one fresh bound process per record.

**Confirmed, high:** the worker writes a valid `complete.json`, then rewrites resources, and the parent rewrites them again. Resume treats any valid marker as final, so a crash in either gap can shorten the contracted wall-time scope while still satisfying cost completeness.

The inference code reconstructs summaries, claims, and Pareto frontiers from complete crossed-seed matrices. **Confirmed, medium:** trajectory parsing censors blank applicable diagnostics, so recomputation cannot detect unused missing fields.

**Confirmed, medium:** the authorization and artifact state machine has no tests; the safe contract check passes, but execution-state transitions and inference assembly remain unexercised.

## Seal-bound orchestration can launch unbound workers (**confirmed**, high)

The seal binds both scripts and every `src/**/*.py` file through the source manifest (`configs/expanded_studies_execution.yaml:438-445`, `configs/expanded_studies_execution.yaml:587-590`). `_worker_prefix` nevertheless accepts any nonempty command without path, hash, interpreter, or source-manifest validation, and `run_scientific_studies` prepends it to every record invocation (`src/gradient_starvation/expanded_studies.py:2088-2102`, `src/gradient_starvation/expanded_studies.py:2118-2126`, `src/gradient_starvation/expanded_studies.py:2168-2189`).

```
sealed source + preflight
          |
          v
 parent verifies authorization
          |
          +---- bound default worker
          |
          +---- arbitrary worker_command  <-- not sealed
                       |
                       v
             self-consistent trajectory
```

The parent recomputes summaries from trajectories but does not reproduce training, so an alternate command can manufacture canonical rows and hashes that receive provenance naming the sealed source. Isolation is also bypassable: `run_record_worker` is exported and callable repeatedly in one process, while validation only requires a positive `worker_pid` (`src/gradient_starvation/expanded_studies.py:1835-1857`, `src/gradient_starvation/expanded_studies.py:2016`, `src/gradient_starvation/expanded_studies.py:3062-3066`; `scripts/run_expanded_studies.py:53-64,94-103`). This contradicts the frozen one-fresh-process and exact-bound-implementation requirements (`configs/expanded_studies_execution.yaml:274-276`, `configs/expanded_studies_execution.yaml:600`).

Fix the production worker to the sealed script and interpreter. A test seam can inject process launching beneath fixed argv; the parent should emit per-record launch/finalization evidence that final validation checks.

## Completion is visible before resource finalization (**confirmed**, high)

`_write_record` writes `resources.json` and a hash-valid `complete.json` (`src/gradient_starvation/expanded_studies.py:1801-1818`). The worker then resamples elapsed time/RSS and replaces both files, after which the parent performs two more replacement cycles for process-launch-through-marker timing (`src/gradient_starvation/expanded_studies.py:1936-1952`, `src/gradient_starvation/expanded_studies.py:2027-2041`, `src/gradient_starvation/expanded_studies.py:2197-2200`).

A kill after the first marker leaves timing sampled before serialization; a parent crash before its rewrite leaves `parent_wall_time_seconds` equal to worker-local time. Resume sees the marker, validates it, and continues without a finalization-state check (`src/gradient_starvation/expanded_studies.py:2162-2166`). Either record can satisfy `cost_complete`, which checks only finite ratios, positive RSS, and CPU CUDA status before enabling the CDC cost conjunct (`src/gradient_starvation/expanded_studies.py:2504-2535`).

This violates the atomic marker and wall-time contracts (`configs/expanded_studies_execution.yaml:275-287`, `configs/expanded_studies_execution.yaml:604-605`). The worker should publish a nonfinal bundle; after validation and parent timing, the parent should create the only `complete.json`. Resume must reject or explicitly recover nonfinal bundles.

## Canonical censorship defeats fail-closed diagnostics (**confirmed**, medium)

`_MANDATORY_FINITE_FIELDS` excludes exact-drift, equal-time decomposition, and most CDC correction columns (`src/gradient_starvation/expanded_studies.py:186-212`). Normalization blanks other nonfinite values, and parsing accepts those blanks whenever `nonfinite_fields` names the blank applicable columns (`src/gradient_starvation/expanded_studies.py:1449-1463`, `src/gradient_starvation/expanded_studies.py:1536-1575`).

A Study-A `direct_drift_s` or decomposition value, or a shadow-method `cdc_alpha`, can therefore be blank on an applicable `both` row and pass. Because not all such fields feed `_summarize_record`, final validation can still return `valid: true`, contrary to the fail-closed artifact and complete-diagnostic rules (`configs/expanded_studies_execution.yaml:339-350`, `configs/expanded_studies_execution.yaml:649-650`).

Keep structurally inapplicable cells blank, but require every applicable numeric field to be finite. Any legitimate nullable field and its effect on claim eligibility needs an explicit frozen schema.

## Authorization and artifact state transitions have no tests (**confirmed**, medium)

No `tests/**/*.py` file imports `gradient_starvation.expanded_studies` or invokes `run_expanded_studies`; the existing expanded-study test covers only the older preregistration validator. Static compilation and the safe `contract` command validate syntax, semantic hashes, linked files, and counts, but not this state machine.

Not tested: the authorization boundary, worker binding, crash-safe resume/finalization, fail-closed artifact handling, or pure bootstrap/Holm/CDC claim assembly. Toy fixtures and fixed matrices can cover these without touching scientific seeds.
